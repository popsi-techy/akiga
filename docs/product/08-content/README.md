# 08 · Content & Language

The product's voice and vocabulary. Consistent language is a core part of enterprise trust — and
the glossary is the canonical dictionary every other document (and the UI) must obey.

> **Populated.** · **Feeds:** `glossary.json`

| Document | Purpose |
|----------|---------|
| `copywriting-guidelines.md` | **Tone and content rules** — voice, tone, capitalization, button labels, dialog wording, empty-state copy, notification wording, and error messages. The style guide for all product text. |
| `terminology.md` | **Preferred vs. avoided terms** — the canonical word for each concept and the near-synonyms we do *not* use (e.g. "entitlement" not "permission" in UI). Enforces consistency and disambiguates competitor vocabulary. |
| `glossary.md` | **The canonical IGA dictionary** — every term with a precise definition, synonyms, and related terms. The vocabulary the whole product is built on. Mirrored in `glossary.json`. |

> Rule: a term must exist in the glossary before it's used in any doc or UI. New concept → new
> glossary entry first.
